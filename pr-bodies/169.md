## What

One `ready` run now reads the default branch's workflow texts and `no_ci`'s answer once, through `ReadyLookups`, however many done lanes have a PR with no checks. Before, each such lane re-fetched `.github/workflows/` and every workflow file (`uncovered_line`), after `checks_state` had already run `no_ci` (up to three `gh` calls), spending `ready`'s 75 s budget on identical calls.

## How

- `ReadyLookups.once(fn, repo)` keeps what `fn(repo)` returned or raised for the rest of the run, keyed by function and repo. A call that timed out is not kept, so the next lane asks again and times out too (listed as skipped), as `ReadyLookups.prs` already does. `ReadyLookups.no_ci` and `ReadyLookups.workflow_texts` go through it.
- `uncovered_line(pr, repo, texts_of=None)` and `checks_state(rollup, repo=None, no_ci_of=None)` take the lookup to use; the default is the plain function, looked up at call time.
- `ready_done` passes the `ReadyLookups` methods when it has one. `waitchecks`, `merge` and `ci_case` keep their own lookups, unchanged.
- A failed (not timed out) workflow read is kept too: later lanes stay at `no checks reported` without asking again. That is the safe side; nothing is merged on a failed read.
