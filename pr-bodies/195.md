## Why

In an app-made worktree, `git push -u origin HEAD` lands the push but fails to write the main checkout's protected `.git/config`, so the branch gets no upstream and a later bare `git push` sends nothing. Lane 182 reported `done` at a head origin never saw; only the coordinator's next `ready` caught it.

## What changed

- `relay.py status` with `--state review` or `--state done` and a real branch and head now runs `git ls-remote origin <branch>` and refuses, writing nothing, when origin has no such branch or holds another sha. The error names the head, origin's sha (or the missing branch) and `git push origin HEAD`. A failed lookup also refuses. `working`, `blocked`, `parked` and `--head none` are unchanged.
- A lane whose plan.md Now Kind is `run`, `audit` or `spare` skips the check: it opens no PR, so its head need not be on origin (the lane-110 pattern `ready` already lists under Finished).
- `relay:work` pushes with `git push origin HEAD` in step 1 and in *Catching up*; no `-u` and no bare `git push` remain.
- The docstring's `status` section describes the new failure and the skip.
- Tests: pushed head, unpushed head, missing remote branch, a failed lookup, unaffected states, and the no-PR skip.
