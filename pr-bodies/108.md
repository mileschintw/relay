## Summary

`ready` gets shorter and its plan warning becomes hard to miss: the plan limit counts bytes, the Plan warning prints first, merged lanes that have left the Now table are no longer listed, and records with a bare CR or mixed line endings are flagged.

```diff
 cmd_ready
-  plan.md lines > --plan-limit (200)          # one 3,247-char line slipped past
+  plan.md bytes > --plan-limit (16384)
-  Lanes: ... sections ... Plan: (last, cut by head/grep)
+  Plan: (first) / Lanes: ... sections
+  done lane whose key is not in plan.md's `## Now` table and whose only line is Merged
+    -> no line; one "(N merged lanes not in plan.md's Now table left out)"
+    (any other line, e.g. Ready for PR or Inconsistent, lists it as before;
+     no `## Now` section -> every lane listed, as before)
 check_encoding
-  bare CR -> "control character U+000D"
+  bare CR -> "bare CR"
+  endings=True: "<file>: mixed line endings (N CRLF, M LF)"
+  checked: plan.md, plan-history.md (new), briefs/*.md
+now_keys(plan)   # first column of plan.md's ## Now table, or None
```

Plan template header: an entry moves to `plan-history.md` the moment it is DONE or CONFIRMED; a ruling moves once its lanes merge or a repo doc carries it; Rulings no longer "always stay". coordinate *Plan*: the same move rule, the 16 KB byte limit, and the "never a shell rewrite" rule replaced by one invariant (the plan, plan-history.md and briefs keep UTF-8 and LF endings; `ready` flags a bare CR or mixed endings).

How `ready` tells a lane moved to `plan-history.md`: its key is not in the first column of plan.md's `## Now` table and its lookups produce only a Merged line. The coordinator moves a lane out of Now after the merge (*Finishing a lane* step 6), so that is the moved state; checking Merged too keeps an unmerged done lane visible if Now is empty or a key left it early.

## Merge Danger

**Door:** two-way

**Blast Radius:** small

`--plan-limit` changes unit from lines to bytes: a caller passing `--plan-limit 200` would now warn on any plan over 200 bytes. No skill passes it. A records folder whose plan has no `## Now` heading keeps the old full listing.

## Review

- Standards: a done lane outside Now was hidden before any lookup, so an unmerged one (empty Now table, key moved early) lost its Ready for PR and Inconsistent lines. **Fixed:** it is left out only when its one line is Merged; tested.
- Standards: the *Plan* Records bullet asked the Edit tool to convert line endings, which it cannot. **Fixed:** "rewrite the whole file as UTF-8 with LF endings".
- Standards: "`ready` lists no done lane ..." was a negation. **Fixed:** "leaves out a merged lane once its key leaves the Now table".
- Standards: the template header dropped "or a repo doc carries it" for rulings. **Fixed.**
- Spec: the header's "moves the moment it is DONE" could lead a coordinator to move a done but unmerged lane, which `ready` would then hide. **Fixed** by the Merged check above.
- Note, left as is: the template's Rulings placeholder still names only "a repo doc or ADR" as the move trigger; it is outside this lane's files (header line only) and does not contradict the header.
- Note, left as is: `now_keys` does not read a key inside a link or a `## Now (3)` heading; the template's table has neither.
- Note, left as is: "CONFIRMED" is the issue's word and is not in GLOSSARY.md.
- Note, left as is: a plan that is CRLF throughout is not flagged; `.gitattributes` and its own Records warning cover that.
- Note, left as is: `check_encoding`'s `endings` flag argument; `READY_SECTIONS` keeps Plan first only for the dict order.
