## Why

`relay.py ready` stalled every `done` lane with `lookup failed: project.md's deny list <records>\none. does not exist`. The setup template's lines all end in a period, so a user who fills in the Deny list as `none` writes `none.`, and `deny_patterns` compared the value to `none` exactly.

## What changed

- `deny_patterns` (plugin/tools/relay.py) now reads the whole value after `- **Deny list:**`, strips backticks and double quotes, and drops one trailing period, both before the `none` check and before resolving the path. `none.`, `none`, `"none"`, `` `none` `` and `` `none`. `` give no patterns. `deny.txt.` resolves to `deny.txt`.
- Decision on "which form wins": the trailing period is always dropped. A file whose name ends in a period cannot exist on Windows, so a "literal name wins" rule could not be tested there.
- A value that is not a file now raises `project.md's deny list <path> is not a file`. This covers a missing path, a directory such as `..`, and a line with trailing notes such as `` `deny.txt` (see notes) ``. Before, a directory failed later inside `read_text`, and a line with trailing notes did not match the regex at all, so it silently meant "no deny list".
- tests/test_relay.py: `test_deny_list_none_and_trailing_period` covers each of the forms above, and checks that a lane in `done` reaches *Ready for PR* when the Deny list says `none.`.

The setup template's Deny list line is unchanged (the issue lists that as optional). The parser now accepts the template's period, so the line works as it stands.

## Review

- Round 1 (standards and spec, in parallel):
