## What

Four fixes in the deny-list path of `plugin/tools/relay.py` (`deny_patterns`, `deny_regex`):

- **BOM:** the deny file's leading UTF-8 BOM is dropped before decoding, so the first line's name matches again (files from PowerShell 5.1 `-Encoding UTF8` or Notepad "UTF-8 with BOM").
- **Not UTF-8:** a UTF-16 or cp1252 deny file now gives one line naming the file and the line of the first bad byte, `project.md's deny list <file> line <n> is not valid UTF-8`, in the same shape as the existing unusable-pattern line. `ready` lists it under Records (done lanes wait with `deny-list check not run (see Records)`); `merge` stops with `...; nothing merged`. Neither the codec message nor the file's text is printed.
- **Zero-length matches:** a pattern whose wrapped form gives a zero-length match in a fixed probe text (`DENY_PROBE`), such as `\b`, `\B`, `(?<=\w)` or `(?=[a-z])`, is refused by line number, like any unusable pattern. Before, these passed the empty-text check and flagged every line of every PR body.
- **`(?x)` comments:** under a leading `(?x)`, the wrapped pattern ends with a newline, so a `#` comment no longer comments out the wrapper's closing part.

The `--help` text and docstrings say all four.
