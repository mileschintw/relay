## Summary

`relay.py ready` no longer lets a `cancelled` or `skipped` push run hide an older failure on the default branch. For each workflow, it walks the runs newest first, passes over `cancelled` and `skipped`, and lets the first run that completed with any other conclusion decide. A newer success still clears an older failure. This reverses #174's rule, per the user's retrospective decision (2026-11-03).

```diff
 ready_push_runs   # one `gh run list --event push`, newest first, per workflow
   not completed           -> note "in progress", keep walking
+  cancelled | skipped     -> note "passed over", keep walking
   anything else decides:
     failure | timed_out | startup_failure -> one line (+ "(a newer run is in progress)")
+                                                       (+ "(newer runs cancelled or skipped)")
```
