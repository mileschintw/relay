## What

Four fixes in `plugin/tools/relay.py`, each with a test that failed before the change:

- **Checks lines.** `check_commands` raises when one `;`-separated item holds more than one backticked command (a `(Windows: …)` override still counts as one). `localcheck` turns that into exit 2 and prints the line, so `` `npm test`, `npm run lint` `` never runs only `npm test`.
- **Deny list.** Patterns are matched with `(?<!\w)(?:pat)(?!\w)` instead of `\b…\b`, so names that start or end with a non-word character (`@acmebot`, `C\+\+`, `\.internal`) are found.
- **status.** It exits 2 when the records folder does not exist, and creates only `status/` inside an existing one, so a mistyped path no longer writes somewhere the coordinator never reads.
- **ready after a failed fetch.** When `git fetch` in `ready --checkout` fails, the merge-tree conflict check is skipped. The Ready for PR / Ready to merge line ends `(conflict check skipped: fetch failed)` instead of reading a stale or missing `origin/<branch>`.

`plugin/skills/setup/templates/project.md`: the Checks before done and Local checks lines show the `` `npm test`; `npm run lint` `` form and the one-command-per-item rule.

The module docstring now states the new rules: the exit-code paragraph, the deny-list and `--checkout` lines under `ready`, and the `localcheck` paragraph.
