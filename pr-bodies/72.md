## Summary

`ready` made one `gh pr list --head <branch>` call and one `git ls-remote` call for every done lane, merged or not: about 1.1 s per lane ever run. It now looks both up once per run:

```diff
 cmd_ready
-  git fetch -q origin
+  git fetch -q --prune origin                       # checks the exit code
+  ReadyLookups(checkout, fetched, lanes)            # shared by every done lane
 ready_done(..., lookups=None)
-  pushed_head(): git ls-remote origin refs/heads/<branch>      # per lane
+  lookups.pushed(): one git for-each-ref refs/remotes/origin   # per run
-  gh pr list --head <branch> --state all                       # per lane
+  lookups.prs(): one gh pr list --state all --limit max(100, 3 x lanes)
```

- **Pushed heads** come from the checkout's `origin/*` refs, which were just fetched with `--prune`. Without `--checkout`, or when the fetch or the ref read fails, they come from `git ls-remote` per lane as before.
- **Pull requests** come from one `gh pr list --state all` call, looked up by `headRefName`. When the list hits its `--limit`, a branch with no merged PR in it gets its own `--head` lookup, because older PRs may be cut off.
- **Deleted branches:** a lane whose branch was deleted after its merge shows under Merged. This holds only when the merged PR's head is the status head, so a reused branch name still shows as not pushed.
- **A failed `ls-remote`** (no repo, origin unreachable) now shows as `lookup failed` for the lane instead of `(branch not pushed)`.
- **`merge` is unchanged:** it calls `ready_done` without `lookups`, so its pre-check keeps one lookup per lane. The signature is compatible and the strings `ready_to_merge` parses are the same.

## Merge Danger

**Door:** two-way. `ready` stays read-only. The one new side effect is `--prune` on the `--checkout` fetch, which removes remote-tracking refs for branches deleted on origin.

## Review

- **Blocker, fixed:** a merged PR on a deleted branch counted as Merged without its head being compared to the status head. A reused branch name could therefore pass. It now requires `headRefOid` to match the status head.
- **Blocker, fixed:** the fetch's exit code was ignored, so a failed fetch read stale refs. A failed fetch or `for-each-ref` now falls back to `ls-remote`.
- **Blocker, fixed:** in a full list, a branch that had some PRs inside the limit skipped its own lookup, so an older merged PR could be missed. It now skips its lookup only when the list has a merged PR for it.
- **Blocker, fixed (round 2):** a successful ref read with no refs ran `for-each-ref` again for every lane. A flag now records that the refs were read.
- **Fixed:** `MERGED` was tested three times in `ready_done`; it is now one `next(...)`.
- **Note, left as is:** `--limit` scales with the lane count, not the repo's PR count. In a repo with many non-lane PRs, old merged lanes fall off the list and get per-branch lookups. Output stays correct; only the speed suffers.
- **Note, left as is:** `ReadyLookups.prs` takes `repo` on each call, because `cmd_ready` resolves `repo` lazily per lane. The list is built from the first `repo` it is given, and `ready` uses only one.
- **Fixed:** a `--checkout` that is not a git repo, or an unreachable origin, made every lane `(branch not pushed)`. `pushed_head` now raises, so each lane shows `lookup failed`.
- **Fixed:** a failed PR list was re-raised as the same exception object for every lane. It is now a fresh `RuntimeError` with the same message.
- **Fixed:** the fake gh's `prs` note moved into its docstring.
