The 0.3.6 release review over `relay--v0.3.5..main` found one code bug and two lines of skill text that contradict the code. `wait_push_run`, which `merge` and `waitchecks --push` share, returned 0 whenever no run failed and not every run was cancelled or skipped. So push runs that all ended `neutral` or `action_required` passed the release gate even though no run had passed. Separately, work step 4 listed changed paths without `--no-renames`, which `localcheck` uses, and coordinate's **Merge** paragraph said `merge` always waits for a push run.

Closes #216

## What changed

- `wait_push_run` now returns 0 only when at least one run ended in `success` and none failed. It checks this against a new `PUSH_RUN_PASSED = ("success",)`, defined next to `PUSH_RUN_FAILED` and `PUSH_RUN_PASSED_OVER`. If no run succeeded, it prints `no push run on <base> for <sha> passed: none ended in success` and exits 3 (`NO_CHECKS`). Failures and timeouts still take precedence, as before. When every run was cancelled or skipped, it keeps its own message.
- I updated the relay.py text to match the new rule:
  - in the module docstring, the exit-3 wording for `waitchecks --push` and for `merge` ("none appeared or none passed");
  - the exit-3 hints for `waitchecks` and `merge`;
  - `wait_push_run`'s docstring.
- `plugin/skills/work/SKILL.md` step 4: the covers diff is now `git diff --name-only --no-renames origin/<default>...HEAD`, the same path list `localcheck` uses.
- `plugin/skills/coordinate/SKILL.md` › **Merge**: adds "(when no workflow runs on `push`, it says so and exits 3 without waiting)". This is the behaviour since #209.
- No other skill text changed.

## Tests

- `PushWaitTests.test_only_a_success_passes`:
  - all runs `neutral` → 3;
  - all runs `action_required` → 3, with the "passed" line;
  - `skipped` + `neutral` → 3;
  - `skipped` + `success` → 0;
  - `neutral` + `failure` → 1.
- The rest of `PushWaitTests` still passes, including `cancelled`/`skipped` → 3 and `cancelled` + `success` → 0.
