## Summary

`waitchecks --push` takes a short sha: it resolves the sha to the full one through GitHub, so no checkout is needed, and then waits as before.

```diff
 cmd_waitchecks --push <sha>
-  not 40 hex characters → exit 2 ("a short one matches no run")
+  not 7 to 40 hex characters → exit 2
   gh repo view → repo, default branch
+  full_sha(repo, sha)
+    40 characters → as is, no lookup (as before)
+    else gh api repos/<repo>/commits/<sha> --jq .sha
+      HTTP 422 (matches no commit, or several) → exit 2, "(not pushed?), or more than one: give more of the sha"
+      other failure, or an answer that is not that prefix's full sha → exit 4 (lookup failed)
   wait_push_run(repo, base, <full sha>, schedule)
```

- `docs/releasing.md` step 2 drops the "giving the full sha (a short one matches no run)" caveat.
- The module docstring (`waitchecks` section, exit 2 and exit 4) and the `--push` help describe the short sha.
- `tests/fake_gh.py` answers `api repos/<repo>/commits/<sha>` from a new `commits` key. A sha missing from that key gets HTTP 422.

GitHub answers HTTP 422 `No commit found for SHA` both for a prefix that matches nothing and for an ambiguous one. This was checked live on 2026-11-03: `0000000` on this repo, and `abcd` and `abcde` on torvalds/linux, all returned it. So both cases share one exit-2 line.
