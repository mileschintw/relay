## What

When `project.md` has the optional `- **relay.py:** <path>` line, the coordinate and work skills run that `relay.py` instead of the installed plugin's `../../tools/relay.py`. This lets relay coordinate its own repo with the checkout's code, so each merge to `main` gets exercised by the next coordinator run.

## Why

On 2026-10-30 the installed plugin was 0.1.0 while ten PRs merged into `main`. None of their `relay.py` changes ran in the session that coordinated them, and the Deny list `none.` bug (#11) stalled every done lane because the old copy was the one in use.

## Changes

- `plugin/skills/coordinate/SKILL.md`, `plugin/skills/work/SKILL.md`: the sentence that defines `relay.py` now resolves it from `project.md`'s **relay.py:** line, with `../../tools/relay.py` as the fallback when the line is absent. Every later call uses the bare name `relay.py`, so this one sentence covers `status`, `ready`, `roadmap` and `localcheck`.
- `plugin/skills/setup/templates/project.md`: a new optional **relay.py:** line, worded like **Local checks:**. It recommends an absolute path, because a relative one resolves against each session's own checkout (a worker's lane worktree, for example).

## Not in this PR

relay's own records (`project.md` on the `coord` branch) still need the line set to the main checkout's `plugin/tools/relay.py`. That is the coordinator's job, since workers don't edit `project.md`.
