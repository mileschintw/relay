## Summary

An issue body's `## Files` section is now the source of the roadmap's **Files it owns** column and of the overlap check when a lane starts. `relay.py roadmap` prints one Roadmap row per open issue: GitHub's blocked-by list and the Files section's paths. An issue with no section, or an empty one, is flagged as missing; its paths are never guessed.

```text
roadmap [--repo]
  open issues (gh api, paginated)
    blocked_by        -> "#1 (closed), #4" | "none"
    sub-issues?       -> "parent"
    parse_files(body) -> None / []  -> "**missing: ...**" + listed under the table
                      -> [{path, new, scope}] -> "New: a.py (scope); b.py"
```

`parse_files`: the section starts at `## Files` (a trailing colon is accepted, and so is an indent of up to 3 spaces) and ends at the next `#`/`##` heading; `###` stays inside. Only top-level bullets count (the first bullet's indent sets the top level; a `[ ]` checkbox is dropped); prose lines, nested bullets and fenced blocks are skipped. `New:` marks a file the lane creates; a trailing balanced `(...)` becomes the scope; a backticked path may contain spaces.
