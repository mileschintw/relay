## Summary

New `relay.py waitchecks <records> <N> [--repo <owner/name>]`. *Finishing a lane* step 4 runs it in the background instead of a bare `gh pr checks <N> --watch`, which exits at once with "no checks reported" when CI has not registered yet.

```text
waitchecks <records> <N>
  schedule = ci_start_schedule(records)      # project.md `CI start wait:` (default 6 min)
                                             #   -> polls at 0, 1/6, 1/2, all of it (0, 1, 3, 6 min)
  wait_checks(pr, repo, schedule)            # callable from another subcommand (#45 merge)
    at each poll: gh pr view <N> --json statusCheckRollup
      any check (queued or pending counts) -> gh pr checks <N> --watch
        exit 0                      -> 0 passed
        exit != 0 and a failed check -> 1 failed
        exit != 0 and none failed    -> 4 lookup failed (a gh error, not a failed check)
      lookup failed                  -> retried at the next poll
    none by the last poll            -> 3 "no checks appeared" (+ "no CI configured" when no_ci)
    last poll's lookup failed        -> 4
```

```diff
+  4. run `relay.py waitchecks <records> <N>` in the background (exit 0, 1, 3, 4)

```
