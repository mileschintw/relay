The repo had no CI, so `relay.py ready` showed every PR as `no checks reported` and the coordinator had to run the checks by hand before each merge. This adds a GitHub Actions workflow that runs those checks.

Closes #16

## What changed

- `.github/workflows/test.yml` (new). It runs on `pull_request` and on pushes to `main`, with a read-only token.
  - `test` job: a matrix of `ubuntu-latest` and `windows-latest` with `fail-fast: false`. Each runs `python -I tests/test_relay.py` after `actions/setup-python@v5`. It uses `python` rather than `python3` because `setup-python` puts `python` on PATH on both OSes.
  - `validate` job: on Ubuntu, `npm i -g @anthropic-ai/claude-code`, then `claude plugin validate .`. This runs without sign-in, so it is in CI instead of staying a local-only check.
  - Actions are pinned to major versions: `actions/checkout@v4`, `actions/setup-python@v5`, `actions/setup-node@v4`.
- `README.md`: one new row for the workflow in the Layout table.

`relay.py localcheck` (#7) stays the fallback for when CI cannot run.
