## Summary

A fallback for *Finishing a lane* when CI cannot run (billing, quota), and `ready` no longer calls a billing-blocked check a failed test.

```text
relay.py localcheck <records> <key> [--checkout <dir>] [--comment <N>]
  command  = project.md "Local checks" line, else "Checks before done", else exit 1 naming both
  git fetch; head = lane's pushed head (from its status file's branch)
  temp worktree --detach at head (core.longpaths=true)
    merge origin/<default>          # a failed merge ends the run, exit 1
    run each backticked command     # "(Windows: `...`)" picked on Windows; "main checkout only" listed as not run
  remove the worktree (also when a check fails)
  print head + base shas and each command's output
  --comment N: post that output on PR N
```

```diff
 checks_state(rollup, repo)
   pending                          -> "checks pending"
-  FAILURE                          -> "check failed: <name>"
+  FAILURE, job never started       -> "checks could not run (billing): <names>"
+     (no steps, or an annotation: "was not started" / spending limit / payments have failed)
+  FAILURE otherwise, or the job lookup failed -> "check failed: <name>"
```

- `plugin/skills/coordinate/SKILL.md`, Finishing a lane step 4: when CI cannot run, ask the user; on their yes, run `localcheck --comment <N>` and merge with `--match-head-commit` set to the head it printed, once that is still the PR head.
- `plugin/skills/setup/templates/project.md`: a **Local checks** line.
- `README.md` Layout table: names `localcheck`.
