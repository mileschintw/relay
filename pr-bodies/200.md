`relay.py status --state review|done` checks origin's head with `git ls-remote`, and before this change nothing bounded that call. Outside `ready` there is no deadline, so a credential prompt, a hung SSH connection or a slow network could block `status` indefinitely, and the coordinator would see a stale status file.

Closes #200

## What changed

- `pushed_head` takes an optional `timeout` and runs `ls-remote` with git's credential prompts off: `GIT_TERMINAL_PROMPT=0`, plus `GCM_INTERACTIVE=never` for Git Credential Manager's window (new `no_prompt_env()`; `run()` gains an `env` parameter).
- `status` passes `STATUS_LOOKUP_SECONDS` (30). A lookup that times out fails like a failed `ls-remote`: exit 1, nothing written, `could not check the head on origin: git ls-remote origin <branch>: timed out after 30 s`.
- `ready`'s lookups pass no timeout, so `ready`'s deadline still bounds them as before. They now also run with prompts off, so a prompt fails at once instead of using up the budget.
- `GIT_SSH_COMMAND` is deliberately not set. As an environment variable it would override the user's `core.sshCommand` or `GIT_SSH`. An ssh passphrase or host-key prompt is bounded by the timeout instead.
- The docstring's `status` section states the prompt-off rule and the 30 s limit.

## Tests

- `StatusTests.test_a_hung_lookup_times_out_and_writes_nothing`: a fake ssh (`GIT_SSH_COMMAND`) sleeps past a patched 2 s timeout. `status --state done` fails with the lookup's name, leaves the status file byte-identical, and the fake saw `GIT_TERMINAL_PROMPT=0`.
- `StatusTests.test_lookup_env_never_prompts`: prompts stay off even when the user's environment turns them on, and the user's `GIT_SSH_COMMAND` is kept.
- `test_review_and_done_pass_on_a_pushed_head` still passes: a pushed head is still accepted.
- Two `ReadyLookupTests` fakes of `run` now pass its new keyword arguments through (`**kw`), and two `pushed_head` mocks take `timeout=None`.

## Review

Standards and spec reviews against #200 and the lane brief found no blocker. The full suite then caught two `ready` tests whose `run` fakes rejected the new keyword arguments; the fix was reviewed as a second round (test fakes only, no blocker). Notes, left as they are:
- The no-prompt env also reaches `ready`'s and `localcheck`'s `pushed_head` calls. Their deadline behaviour is unchanged; it is stated above and has no `ready`-specific test.
- An ssh prompt is not refused, only bounded by the 30 s timeout, since setting `GIT_SSH_COMMAND` would override the user's ssh config. The issue's "for example" allows this.
- On timeout, `p.kill()` kills `git` but not an ssh grandchild. The existing 2 s drain cap keeps `status` from waiting on it. In the test, the fake ssh sleeps on for about 18 s after the test.
- The test's fake ssh must write its marker within 2 s on a slow runner. The risk is low.
- The `pushed_head` mocks and `run` fakes in tests needed the new parameters. `*a, **k` stubs would survive the next signature change. Another lane's new fake of `run` with only `(cmd, cwd=None)` would break the same way if it reaches `pushed_head`.
- `STATUS_LOOKUP_SECONDS` could sit next to `READY_SECONDS`.
- `localcheck` has the same hang on its `git fetch` and lookup; that is out of this lane, filed separately. Refs #211
