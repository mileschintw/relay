## What changes

`waitchecks` and `merge` now exit by what CI and GitHub report, never by a Python error. The checks watch prints once. `ready`'s relay.py warning no longer suggests a command that would move or fail. A `project.md` that is not UTF-8 is a warning, not a crash.

- **waitchecks / merge (`main`):** stdout and stderr are reconfigured with `errors="replace"`, so a check name a cp1252/cp950 console cannot hold no longer raises. Any error the code does not name (a bug, a bad byte from `gh`) exits **4** with one line `<cmd>: unexpected error: <Type>: <message>`, never 1.
- **Watch output:** `gh pr checks <N> --watch` runs with its stdout discarded (with no terminal it reprints the table every 10 s). Then `gh pr checks <N>` runs once and its table is printed. Errors from both calls go to stderr.
- **`relay_py_behind` (#47):** on the default branch, with nothing of its own, the fix stays `git -C <checkout> merge --ff-only origin/<default>`. On another branch or a detached HEAD, or with commits ahead of origin, the warning says so in plain words and offers no command. It never suggests `switch`.
- **`project_line`:** a non-UTF-8 `project.md` raises a `ValueError` that names the file, instead of a bare `UnicodeDecodeError`. `ready` adds `project.md` to its Records encoding check (one `project.md line N: invalid UTF-8` warning), and `relay_py_behind` skips its check. `ready` completes.
- **merge:** a key given twice exits **2** (a usage error, as the docstring says) and runs no lookup. `--checkout` defaults to `.`, so the fetch and the `merge-tree` conflict check always run, as for `ready --checkout`.
- `LOOKUP_ERRORS` moved to the top and replaces the inline exception tuples (`wait_checks`, `cmd_waitchecks`, `cmd_ready`'s per-lane `try`, `cmd_localcheck`'s comment post).
- The docstring's ready (Records, relay.py), waitchecks and merge sections, and its Exit paragraph, now match the code.

### Exit codes that changed (for docs naming them: coordinate SKILL.md step 4, `ci-fallbacks.md`)

- `merge`: a repeated key, **1 → 2**. New: **4** on an unexpected error, which used to be a traceback and exit 1. Lookup, merge-state and `gh pr merge` failures still exit 1 ("stopped").
- `waitchecks`: an unexpected error (an encoding error, say) is now **4**, not a traceback and exit 1. A non-UTF-8 `project.md` exits 2, as it already did, and is now documented.
