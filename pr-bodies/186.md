The test suite builds real git repos, and until now each one picked up the machine's own git config and git version. Lane 174's `test_no_origin_head_is_a_failed_lookup_not_a_guess` passed on Windows (git 2.38) and failed on ubuntu CI (git 2.48+), because newer git re-creates `origin/HEAD` on fetch. The fix in 8d86608 patched that one test. This PR isolates git for the whole suite instead.

## What changes

- `setUpModule` in `tests/test_relay.py` writes a harness-owned gitconfig to a temp dir. It then points `GIT_CONFIG_GLOBAL` at that file and sets `GIT_CONFIG_NOSYSTEM=1` for the whole module run, restoring the environment afterwards. Every git the tests start inherits this, including the git that `relay.py` and `resume.py` run.
- The file holds a fixed identity (`t` / `t@example.com`), `init.defaultBranch = main`, and `remote "origin".followRemoteHEAD = never`.
- `setUpModule` also drops `GIT_CONFIG_COUNT` and `GIT_CONFIG_PARAMETERS` from the caller's environment, so config injected from outside can't reach the tests either.
- These lines go, since the harness config now supplies them:
  - the per-test `followRemoteHEAD` line in `PushRunTests`
  - `Base.setUp`'s per-clone `user.email` / `user.name`
- New `HarnessGitTests` checks that a subprocess git sees the harness values through `git config --global --list`. It also checks that, outside any repo, every config entry comes from the `global` scope, which means no system config.
