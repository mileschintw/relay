## 各檔案的變更

- `plugin/tools/relay.py`
  - 新增 `localcheck <records> <key> [--checkout <dir>] [--repo] [--comment <N>]`：
    - 指令取自 project.md 的 `Local checks:`；沒有這行（或寫 `none`）時改用 `Checks before done:`；兩行都沒有就以 exit 1 結束，訊息同時指出兩行。
    - 依狀態檔的 branch 取得已推送的 head，在 `%TEMP%\relay-lc-*` 建立 detached worktree（`core.longpaths=true`）。
    - 合併 `origin/<default>` 後逐一執行反引號中的指令，並印出 head、base sha 與每個指令的輸出。
    - worktree 在 `finally` 中移除，檢查失敗時也一樣。
    - `--comment N` 把輸出貼到 PR。
  - 指令解析規則：
    - 以 `;` 分項，反引號內的 `;` 不算分隔。
    - `(Windows: `...`)` 在 Windows 上取代該項的指令。
    - 標記「main checkout only」的項目列為 not run，結果行顯示 `result: passed, N not run: …`。
    - 狀態檔的 head 與推送的 head 不同時，輸出中會有 warning 行。
  - `checks_state(rollup, repo)` 與 `never_started`：
    - 判定為 billing：失敗的 check 有 job URL，而且該 job 沒有任何 step，或有一則 annotation 符合 `was not started|spending limit|payments have failed`。
    - 這類 check 在 `ready` 的 Waiting 下列為 `PR #N checks could not run (billing): <names>`。
    - 真正的失敗優先列出；查詢失敗時視為真正的失敗。
  - `gh` 改為呼叫新增的 `gh_raw`（純文字輸出，`pr comment` 要用），兩者共用 $RELAY_GH 的解析。
  - docstring：新增 localcheck 用法、Waiting 的 billing 說明與 exit code。
  - 輸出前做 `sys.stdout.reconfigure(errors="replace")`：在 cp950 主控台實測時，`claude plugin validate` 的 ✔ 會讓 print 崩潰。
- `tests/fake_gh.py`
  - 新增 `api …/actions/jobs/<id>`、`api …/check-runs/<id>/annotations` 與 `pr comment`（寫入 `$RELAY_FAKE_GH.comments`）。
- `tests/test_relay.py`
  - 新增 11 個測試：billing（無 step、annotation 兩種）、真正失敗仍為 `check failed`、Local checks → Checks before done → 清楚的錯誤、印出 head 與 base sha、失敗後 worktree 已移除、合併失敗、`none`、main-checkout-only、`--comment` 成功與失敗、指令解析。
- `plugin/skills/coordinate/SKILL.md`
  - Finishing a lane 第 4 步新增子項 **CI cannot run**：
    - 先問使用者，同意後執行 `localcheck --comment <N>`。
    - 有 not run 的項目時，先在 main checkout 跑完。
    - 結果通過且沒有 status-head warning 時，確認印出的 head 仍是 PR head，再以 `--match-head-commit` 合併。
- `plugin/skills/setup/templates/project.md`：新增 **Local checks** 行。
- `README.md`：Layout 表的 relay.py 一列加上 `localcheck`。這不在 brief 的檔案清單內，但 project.md 的 test bar 要求 Layout 表同步，所以只改了這一格。GLOSSARY 不需要改。
